How I test AI features

Practice

Traditional test design assumes the same input produces the same output. AI-assisted features break that assumption, and most teams respond by either testing nothing or eyeballing responses until they look fine.

My approach is to make the variable parts explicit: fix everything around the model so a prompt change is the only thing that moved, keep a living corpus of inputs that have caused failures before, and define pass criteria in terms of properties rather than exact strings.

Structured prompt templates

A fixed harness around every prompt so that when output changes, the prompt is the only variable that could have caused it.

Edge-case scenario libraries

A maintained corpus of inputs that have broken something before — ambiguity, adversarial phrasing, empty and overlong inputs, domain edge cases.

Output consistency checklists

Explicit criteria that decide whether a response passes: required fields present, no fabricated entities, tone in range, refusal behaviour correct.

Assertion pattern — sanitized

scenario:  user submits an ambiguous request
fixture:   locked model version, temperature, system prompt
input:     corpus/ambiguous/*.json          (48 cases)

assert response.schema            valid
assert response.entities ⊆ input.entities
assert response.contains_refusal  when input.out_of_scope
assert response.length            within 1..3 sentences
assert response.tone              in [neutral, helpful]

gate:      ≥ 46 / 48 pass  →  promote
           < 46 / 48 pass  →  block merge, diff vs baseline

The point is the gate. Without a threshold agreed in advance, "the output looks worse" is an opinion and nobody can act on it.
